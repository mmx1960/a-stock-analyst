# A 股选股策略文档 v3.1

> 状态：当前主策略（实时选股）  
> 项目：`a-stock-analyst`  
> 策略代号：`v3.1`  
> 维护原则：后续所有策略调整、过滤条件变化、回测结论更新，统一在本文档持续迭代。

---

## 1. 策略定位

`v3.1` 是当前项目的**主实时选股策略**。

它是在 `v3` 标准缠论买点策略基础上，针对真实批量扫描场景做的实战化优化版本，核心目标不是“最纯理论的缠论表达”，而是：

- 保留缠论主干逻辑
- 提升实时扫描速度
- 控制 AKShare 限流风险
- 提高近期可执行信号质量
- 降低无效震荡与过期信号

一句话概括：

> **周线定方向，日线抓回调，背驰/强支撑确认买点，只扫活跃股，只要最近 7 天内的新鲜信号。**

---

## 2. 策略目标

本策略主要解决以下问题：

1. **从全市场中快速筛出近期可能具备上涨潜力的股票**
2. **避免追高，优先寻找上升趋势中的回调买点**
3. **避免扫描过多冷门股，聚焦活跃资金关注标的**
4. **让策略具备“每日可运行、可输出结果”的工程可用性**

本策略适用于：

- 每日/盘后选股
- 活跃股候选池构建
- 后续人工复盘的第一层过滤
- Web 系统中的“今日候选”或“近期买点”模块

---

## 3. 核心思想

策略基于缠论的简化结构表达：

- **周线**：确认大级别背景仍偏多
- **日线**：确认近期发生过有效回调
- **背驰/强支撑**：确认回调不是单纯下跌中继
- **时间窗口**：只保留最近 7 天内的新鲜信号
- **活跃股过滤**：优先扫描成交额 Top 500

这意味着策略不是去抓“所有便宜票”，而是去找：

> **处于中期多头背景中的短期回调结束点。**

---

## 4. v3.1 规则总览

当前 v3.1 应按**五层过滤**理解，而不是零散条件堆叠：

1. **周线趋势上下文**：判断当前是否仍处于上涨段中的回调
2. **长期位置过滤**：历史高点位置 / MA250，过滤长期弱势反抽
3. **前序量价结构**：日线放量阳线 + 缩量回调，或周线慢堆量
4. **日线入场确认**：用 score 模式评估触发质量
5. **小级别二买确认 + 时效过滤**：确保买点不只是日线看起来像，而是 30/60 分钟已确认，且信号足够新鲜

工程原则：

- 所有会影响“是否产生信号”的条件，都应收口到 `analyze_v3_1_signal(...)`
- 实时选股、回测、AB runner 必须复用同一真源函数
- AB 比较必须通过显式开关控制，不允许再靠 monkey patch 或 runner 外围事后切口径

### 4.1 股票池过滤

只扫描**成交额 Top 500 活跃股**。

目的：

- 提升扫描速度
- 避免 AKShare 全量扫描过慢
- 提高信号可交易性
- 让缠论结构更稳定（活跃股更容易形成清晰波段）

实现思路：

```python
df_list = ak.stock_zh_a_spot_em()
df_list = df_list.sort_values('成交额', ascending=False).head(500)
```

### 4.2 周线趋势过滤（默认作为背景，可通过显式开关转为硬过滤）

当前版本保留 `check_weekly_uptrend_context(...)` 作为周线背景判断函数，并输出以下字段：

- `weekly_uptrend_context_ok`
- `weekly_uptrend_reason`
- `weekly_pullback_bars`
- `weekly_context_window`
- `weekly_context_half_below_ratio`
- `weekly_pre_pullback_high`
- `weekly_current_close`

默认情况下：

- `enforce_weekly_context=False`
- 周线过滤仍会计算，但主要作为解释字段输出
- 这样可避免在主流程中过早误杀候选

当需要做更严格实验或 AB 对比时，可通过显式开关切为硬过滤：

- `enforce_weekly_context=True`

当前周线趋势上下文规则：

1. 最近连续周线回调不超过 `6` 根
2. 回调前观察窗口 = 回调长度 × `3`
3. 在该窗口内，至少一半 `high` 低于当前价
4. 回调前的高点必须是该 3 倍窗口内的最高点

简化表达：

> **周线层先负责解释趋势背景，需要时再提升为硬过滤，而不是在所有场景一刀切。**

---

### 4.3 日线回调识别

要求最近有效向下笔满足：

1. 最近存在一笔 `D -> B` 的向下笔
2. 该向下笔为一次真实回调，而不是噪音震荡
3. 回调幅度至少 **3%**

回调幅度定义：

```python
drop = (high_at_bi_start - low_at_bi_end) / high_at_bi_start
```

过滤规则：

- `drop < 0.03` 的回调直接忽略

目的：

- 过滤微小波动
- 提高盈亏比
- 避免过早介入无效横盘

---

### 4.4 买点确认：宽松背驰 / 强支撑

v3.1 在 v3 的基础上，采用更适合实时选股的**宽松确认机制**。

只要满足下列任意一种，即可认为日线回调具备较强买点特征：

#### 条件 A：标准 MACD 面积背驰

最近一笔向下笔相对于前一笔向下笔：

- MACD 绿柱面积明显缩小
- 代码条件近似为：

```python
area_last < area_prev * 0.8
```

含义：

- 虽然价格仍在下探，但下跌动能已明显衰减

---

#### 条件 B：Higher Low（低点抬高）

最近一笔向下笔的低点**没有跌破**前一笔向下笔低点：

```python
price_last > price_prev
```

含义：

- 价格没有创新低
- 市场属于更强的支撑型回调
- 这类买点往往比标准底背离更强势

---

#### 条件 C：零轴上方回踩

如果最近向下笔过程中 MACD 绿柱面积几乎为 0，则视为一种极强结构：

```python
area_last == 0
```

在当前实现中，体现为：

```python
cond1 = (area_last < area_prev * 0.8) if area_last > 0 else True
```

含义：

- 回调时 MACD 没有明显转入弱势负动能
- 更接近主升趋势中的强势整理

---

### 4.5 量能确认：放量回踩 / 周线慢堆量（二选一）

v3.1 现在把量能条件改成**互补式二选一**，满足其一即可继续进入买点确认：

#### 条件 A：日线放量回踩结构

在最近 **50 根 K 线** 内，必须找到一次明确的阳线放量锚点：

- 阳线成交量 / 前 10 根均量 `>= 2.5`
- 该放量阳线之后，到买点出现前的所有阴线
- 成交量都不能重新放大到锚点量能的 `100%` 以上

含义：

- 市场前面确实出现过一次主导性放量攻击
- 后续回调过程中卖压量能明显收缩
- 这类结构更接近“强势拉升后的缩量回踩”

#### 条件 B：周线连续红柱慢堆量

如果没有出现日线级别的明确爆发式放量，也可以走**周线慢慢堆量**这条互补路径：

- 最近周线必须**连续 3 根及以上红柱**（收盘 > 开盘）
- 每根红柱周量与其前 8 周均量相比，属于缓慢抬升
- 当前保留量比信息用于观察，但**不再按量比上限做过滤**

含义：

- 资金不是单纯靠一天日线放量触发
- 而是在周线层面持续温和进场
- 适合补足那些“没有明显单日巨量，但周线资金结构在变强”的票

---

### 4.6 日线入场确认（score 模式 + signal_type 分级阈值）

当前版本已把日线入场确认改成 **score 模式**，不再使用“全满足 / 全不满足”的硬门槛。

检查项共 4 个，每项 1 分：

1. **实体反弹幅度**
   - `(close - open) / open >= 0.01`
2. **收盘远离日内低点**
   - `(close - low) / low >= 0.015`
3. **收盘不弱于前收**
   - `(close - prev_close) / prev_close >= 0`
4. **量能不塌陷**
   - `volume / volume_ma5 >= 0.9`

当前默认阈值不是统一值，而是按 `signal_type` 分级：

- `higher_low -> 2`
- `zero_axis_pullback -> 2`
- `macd_area_divergence -> 3`

输出字段至少包括：

- `entry_ok`
- `entry_reason`
- `entry_signal_type`
- `entry_score`
- `entry_min_score_required`
- `entry_score_max`
- `entry_score_breakdown`
- `entry_failed_checks`
- `entry_body_rebound_pct`
- `entry_close_from_low_pct`
- `entry_close_above_prev_close_pct`
- `entry_volume_ratio`
- `entry_volume_ma5`

解释原则：

- `entry_ok=True` 且无失败项：`entry_reason='ok'`
- `entry_ok=True` 但并非满分：`entry_reason='score_pass_with_soft_failures'`
- `entry_ok=False`：优先返回第一个失败原因，如 `entry_body_too_weak` / `entry_volume_too_low`

这样做的目的不是把规则放松，而是把入场确认从：

- **一票否决式硬门槛**

改成：

- **可解释、可分级、适合 AB 迭代的容错过滤器**

---

### 4.7 缠论二买确认：30 分钟 / 60 分钟（二选一）

在满足周线背景、日线回调、量能条件、日线止跌确认后，买点还必须再满足一层**小级别缠论二买确认**：

- **60 分钟二买** 或 **30 分钟二买**
- 两者满足一个即可

当前工程化判定思路：

1. 小级别最近至少形成两笔向下笔
2. 两次向下笔之间，必须存在一笔向上笔作为结构桥接
3. 第二次向下笔低点要**高于**第一次向下笔低点
4. 第二次向下笔的 MACD 绿柱面积要弱于第一次

简化理解：

> **大级别看趋势和回调，小级别看“回调后的再次确认不破低点”。**

这样做的作用：

- 避免只凭日线回调就直接上车
- 把买点压缩到更具体的二买结构里
- 提高“日线看着不错，但小级别还没止跌完”的过滤能力

---

### 4.8 时效过滤

买点必须发生在最近 **7 天内**：

```python
0 <= days_ago <= 7
```

目的：

- 去掉已经过期的历史信号
- 让选股结果更接近“当前可观察、可执行”的候选池

说明：

- 如果一个买点 2~3 周前已经出现，即使逻辑上成立，也不再计入实时结果

## 5. 数据与技术实现

### 5.1 数据源

- 行情源：AKShare
- 日线复权：`hfq`（后复权）

说明：

- `hfq` 更适合历史趋势判断与回测一致性
- 避免 `qfq` 在老股票上的历史价格失真问题

---

### 5.2 K 线范围

当前实现默认拉取近 **365 天**日线数据：

```python
start = (datetime.now() - timedelta(days=365)).strftime("%Y%m%d")
```

作用：

- 足够形成周线与日线结构
- 控制请求量与计算量

---

### 5.3 分型识别

使用简化版分型识别：

- **顶分型 D**：中间 K 线高点高于前后各两根
- **底分型 B**：中间 K 线低点低于前后各两根

特点：

- 简单、稳定、可快速运行
- 但不处理严格缠论中的包含关系

这意味着：

> v3.1 是“缠论工程化简化版”，不是 100% 严格原教旨缠论实现。

---

### 5.4 成笔规则

分型成笔采用简化规则：

- 顶底分型必须交替
- 间隔至少 3 根 K 线

定义：

- `B -> D`：向上笔
- `D -> B`：向下笔

## 6. 与 v3 的主要差异

### v3（标准缠论买点）
更强调：

- 周线向上背景
- 日线向下笔结束
- 严格背驰
- 底分型确认
- 回测一致性

### v3.1（实时实战版）
额外强化：

1. **股票池缩窄到 Top 500 活跃股**
2. **增加回调幅度 ≥ 3%**
3. **背驰判定放宽为 3 种可选条件**
4. **量能过滤改为二选一：日线放量回踩 / 周线慢堆量**
5. **新增 30 分钟 / 60 分钟缠论二买确认**
6. **只保留最近 7 天内的买点**
7. **串行扫描 + sleep 防限流**

因此：

> `v3` 更像标准回测母策略，`v3.1` 更像可落地的实盘候选池策略。

## 8. 已知优点

1. **更适合真实批量扫描**
2. **信号更聚焦活跃股**
3. **避免大量过期信号**
4. **能抓到上升趋势中的回调低吸机会**
5. **相较全量缠论实现，复杂度明显更低，易维护**

---

## 9. 已知局限

1. **分型和成笔是简化版，不是严格 CZSC 标准实现**
2. **Top 500 股票池会漏掉部分低活跃但高弹性标的**
3. **最近 7 天过滤会漏掉稍早出现但仍可观察的信号**
4. **3% 回调阈值是经验值，后续需回测优化**
5. **Higher Low 与零轴上方回踩的放宽规则会引入更多噪声，需要持续验证**
